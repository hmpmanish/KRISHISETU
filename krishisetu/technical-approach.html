2. Frontend Architecture (Current Prototype)

This SIH prototype is intentionally built as an offline-first, client-side application to ensure flawless demonstration without relying on external network dependencies.

HTML5

Semantic structure and accessibility.

CSS3 (Vanilla)

Custom Glassmorphism UI, CSS variables for theming, completely responsive without heavy frameworks.

Vanilla JavaScript

Handles application state, view routing, mock AI evaluation, and dynamic rendering.

LocalStorage

Acts as the prototype's persistence layer to simulate a live database during workflows.

Mock JSON/Data

Provides simulated market rates, processing opportunities, and verification records.

Decision Engine

Rule-based scoring algorithm running locally to determine batch recommendations.

3. Decision Engine & Explainability

Input Variables

  • Crop Type & Quantity
  • Quality Grading
  • Remaining Shelf Life
  • Market Price (Current + Trend)
  • Spoilage Risk
  • Storage Availability / Cost
  • Processing Suitability

Engine Type: Current Prototype uses a deterministic rule-based scoring system.

Explainability Output

To ensure trust, the system does not act as a "black box". It generates human-readable reasons.

RECOMMENDATION: PROCESS
  • "High processing suitability for this crop."
  • "Shelf life permits processing, avoiding market loss."
  • Risk: "Current market price is weak."

4. Human-in-the-Loop & Trust

"AI Recommends. The Farmer Decides."

The system intentionally forces a manual review step. In the database architecture, AI Recommendation and Farmer Final Decision are stored as separate, immutable fields for auditing and future model training.

5. Trust, Verify & Evidence Layer

Before a farmer initiates a transaction or connection, KrishiSetu provides an Evidence Layer. This prevents fraudulent transactions by displaying verifiable records.

Prototype Verification Record Data Model

{
  "entityName": "AgroFresh Processing",
  "registrationID": "KS-ENT-2026-0047",
  "verificationStatus": "VERIFIED",
  "verificationSource": "MSME Udyam (Simulated)",
  "validityDate": "2027-01-14",
  "proofVault": [ Document Hashes... ]
}

Why Evidence Matters

Providing a simple 'Verified' tick is not enough. The Proof Vault allows the user to see the exact registration document, date of verification, and source authority. Note: Our prototype uses simulated demo data. Production requires API integration with e-NAM, FSSAI, or state registries.

6. Advanced Workflows & Traceability

Rescue Workflow Trigger

Triggered when shelfLife <= 2 OR spoilageRisk === 'Critical'. The UI elevates the batch to the 'Rescue Center' and prioritizes finding immediate buyers or processors over long-term market wait times.

Batch Traceability

Every action taken on a batch is appended to a chronological timeline array. In a production environment, this timeline represents a blockchain-based or immutable ledger entry ensuring farm-to-processor traceability.

8. Farmer Adoption Architecture

Addressing the barrier of digital literacy and smartphone access:

Mode A: Direct Farmer

Simple Hindi/regional UI for farmers comfortable with smartphones.

Mode B: Assisted Access

FPOs, CSCs, or authorized mandi facilitators operate the app on behalf of the farmer.

Mode C: Voice/IVR (Proposed)

Future integration utilizing conversational AI over phone calls for extreme rural reach.

Guiding Principle: "The farmer is the beneficiary, not necessarily the operator."

9. Known Limitations (Hackathon Context)

  • Data Accuracy: This prototype utilizes simulated demo data for market prices, processing opportunities, and entity registries.
  • Decision Algorithm: The current decision engine is deterministic (rule-based). A production engine would utilize trained ML models on historical crop data.
  • No Real API Calls: External calls to real government verification networks or SMS gateways are stubbed/mocked out for demo stability.
  • QR Simulation: The QR scanner is a visual simulation to demonstrate workflow.
  • Security: Proper authentication, JWT, and encrypted databases are bypassed to allow rapid judge evaluation.
